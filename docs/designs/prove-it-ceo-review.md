## Section 1: Architecture
```
 browser (Verify stage panel)
     | POST /api/v1/interop/passport/verify   (reviewer/admin, stateless, size-capped)
     v
 FastAPI handler --> passport.verify_portable(package) --> + verify_signature(package, PUBLIC_KEY)
                                                              ^
 passport.portable(...) at export time --signs head hash---- PRIVATE KEY (env/Secret, never in repo)
```
- OK: no storage, no new tables, one new endpoint, reuse of canonical `digest()`.
- CRITICAL GAP (key persistence): if the signing key changes between restarts, every previously exported passport stops
  verifying. The key must come from a Secret/env var that survives restarts, with its public fingerprint embedded in each package.
- WARNING (legacy packages): packages exported before signing have no signature. They must verify as "UNSIGNED, hash chain valid",
  not as a failure.
- Signature must cover `head hash + record version + object id`, not the head hash alone, or a valid head can be replayed.

## Section 2: Error and rescue map
| Codepath | What can go wrong | Handling required | Test |
|---|---|---|---|
| verify endpoint | body not JSON / not an object | 422 with fixed message | yes |
| verify endpoint | package > size cap | 413 | yes |
| verify_portable | missing keys, wrong types | status INTEGRITY FAILURE (already caught) | exists |
| verify_signature | no signature present | status UNSIGNED, never 500 | yes |
| verify_signature | wrong key / altered head | status SIGNATURE_INVALID | yes |
| export (signing) | private key not configured | export still works, marked UNSIGNED, logged once | yes |
| tamper panel | network error | inline error, panel stays usable | yes |
No catch-all exception text may reach the response (the CodeQL lesson from PR #5).

## Section 3: Security and threat model
- The endpoint is reviewer/admin only, tenant-agnostic (it processes only what the caller sends), logs outcome type only.
- Private key in a Kubernetes Secret and `.env.example` placeholder only; never printed, never committed.
- Residual: signing proves the server issued the passport, not that the lab data is true. Keep the existing limitations text.

## Section 4: Data flow (nil / empty / error)
Happy: edit one value, recompute nothing, verify returns INTEGRITY FAILURE naming the changed artifact.
Nil: no package -> 422. Empty `content` -> INTEGRITY FAILURE. Upstream error: none, fully local.

## Section 5: Code quality
Reuse `digest()` for canonical hashing. Do not reimplement hashing in the UI; the browser sends the edited package and the server decides.

## Section 6: Test review (required)
1. Edit a value in an exported package -> INTEGRITY FAILURE; stored job unchanged (read it back).
2. Edit a value AND recompute every hash -> hash check passes, signature check fails (the forgery test).
3. Unsigned legacy package -> UNSIGNED but hash-valid.
4. Key unavailable at export -> UNSIGNED, export succeeds.
5. Oversized or non-JSON body -> 413 / 422.
6. Role check -> coordinator gets 403.

## Section 7: Performance
Hashing a passport is milliseconds. Cap request size at 1 MB. No concern.

## Section 8: Observability
Log `passport.verify` with status only. Count UNSIGNED exports so a missing key is visible, not silent.

## Section 9: Deployment and rollout
Add `PASSPORT_SIGNING_KEY` (base64 Ed25519 seed) to k8s/cluster.py secret generation and `.env.example`. Rollback = ignore the
signature field; hash verification still works. EXP-2 needs a JRE and `validator_cli.jar` on the demo machine, or a stored result.

## Section 10: Future direction
Signed passports make the deferred offline verifier (EXP-3) tractable: it only needs the public key and the canonical hashing rules.
A published key fingerprint (README) is the cheap trust anchor. Real third-party anchoring is a later step.

## Section 11: UI (tamper panel)
Required states: idle, editing, verifying, result (hash fail / signature fail / valid), error. Label the panel "throwaway copy, nothing is
saved". Keyboard operable, visible focus, result announced via `role="status"`. Do not let the panel enable "edit then save".
