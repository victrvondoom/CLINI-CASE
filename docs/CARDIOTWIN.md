# CardioTwin — cardiovascular risk visualization & vessel-level prediction

> **Decision support / educational use only.** CardioTwin estimates probabilities from tabular clinical features.
> It is not a diagnosis, not a substitute for coronary angiography or other diagnostic imaging, and not a medical
> device. It does not locate, size or characterise any lesion.

CardioTwin is an additive ClinCase / OncoTwin subsystem (route `/cardiotwin`, API `/api/v1/cardiotwin`). It answers
Track A: *predict overall CAD and the stenosis status of LAD, LCX and RCA from clinical data, and show it on an
interactive 3D heart with an explanation.* Everything below — numbers, artifacts, scenarios — is generated by
`python -m app.cardiotwin.training` from the committed dataset; nothing is hand-entered.

## 1. Problem and honest scope

| It **is** | It **is not** |
|---|---|
| Estimated probability of angiographic CAD (the dataset's `Cath` label) | A heart-attack, event or mortality risk |
| Estimated probability of ≥50 % stenosis in each of LAD / LCX / RCA | Lesion localisation, length, plaque geometry or morphology |
| A calibrated, uncertainty-annotated, explained model output drawn on a *schematic* heart | Diagnostic imaging or an anatomically-registered model |

The dataset (UCI id 411, n = 303) has no images, no lesion coordinates and no longitudinal follow-up, so none of
those claims could be supported. The UI says "predicted CAD probability" and "estimated vessel-level stenosis
probability", and repeats the disclaimer on the page header and inside the 3D viewer.

## 2. Novelty investigation (done before designing the system)

Web research (queries on CAD + Three.js / React Three Fiber, Z-Alizadeh Sani + SHAP / calibration / conformal,
cardiovascular digital twins) found:

* **The obvious solution is already public.** [Mohammad-Umar7/CardioTwin](https://github.com/Mohammad-Umar7/CardioTwin)
  is an "explainable 3D coronary-risk digital twin" for this exact dataset: XGBoost + SHAP + a BodyParts3D heart in
  React Three Fiber + FastAPI, with a decision-support disclaimer. (It even shares the name — noted as a naming
  collision.) Its README, as read, does **not** document calibration, uncertainty, OOD handling, counterfactuals,
  leakage handling or reported metrics; absence from a README is not proof of absence in code.
* **Explainable CAD prediction on this dataset is saturated** — many papers/notebooks with RF / XGBoost / SVM + SHAP
  ([Algorithms 2025](https://doi.org/10.3390/a18110697), [PLOS One 2024](https://journals.plos.org/plosone/article?id=10.1371%2Fjournal.pone.0307952)).
  Per-vessel classification on the same data is also published (accuracies ≈ 83–86 %).
* **Uncertainty for CAD on this dataset is published** — RF + conformal prediction on Z-Alizadeh Sani
  ([Frontiers Cardiovasc. Med. 2026](https://www.frontiersin.org/journals/cardiovascular-medicine/articles/10.3389/fcvm.2026.1857390/full)),
  and post-hoc calibration for heart-disease prediction ([medRxiv 2025](https://www.medrxiv.org/content/10.1101/2025.09.28.25336834.full.pdf)).
  Uncertainty per se is therefore **not** novel here.
* Cardiovascular "digital twin" literature is about physics-based / longitudinal models. A cross-sectional
  classifier on 303 rows is a *risk model*, not a twin; the name is inherited from the ClinCase subsystem family.

### Novelty collision report

| Question | Answer |
|---|---|
| What will most teams build? | Tabular ML → SHAP → colour a downloaded heart mesh. Public reference implementation exists. |
| Saturated | CAD classifier accuracy; SHAP bars; a red/amber/green heart. |
| Merely requirements (not novelty) | Leakage-safe features, ROC-AUC/F1, rotate/zoom/select vessels, dashboard, disclaimer. |
| Fake novelty (rejected) | LLM chatbot, agents, blockchain, "AI digital twin" branding, a deep net on 303 rows, fancier shaders. |
| Uncommon implementation (built) | Measured **CAD ⊇ vessel consistency constraint**; exact vessel-specific attribution tied to the 3D selection; **model-sensitivity simulation** with a "within model noise" flag; representativeness warning; auditable provenance panel; leakage canary + bypass demonstration; hash-reproducible training. |
| Uncommon architecture (built) | JSON linear artifact + SHA-256 → numpy-only serving; explanation, counterfactual and sweep are exact re-evaluations of the same artifact. |
| Research-like / genuinely novel | **Nothing claimed.** Each component is known; the contribution is their integration, measurement and claims-discipline. |

**Technical thesis (revised after the research).** CardioTwin is a claims-bounded interface to a calibrated
probabilistic model: every vessel colour is an estimated probability whose calibration, ensemble uncertainty and
cohort-representativeness are *measured and drawn*; vessel estimates obey the logical hierarchy CAD ⊇ any vessel
(which independent models violated for **17.5 %** of patients); and every
explanation and what-if is an exact re-evaluation of an integrity-checked linear artifact — so what is shown is
auditable end-to-end, while the UI states what the data cannot support (no lesion localisation).

If 100 teams received Track A, roughly all would build the baseline; the differences here are mechanisms that change
*what can be trusted*, not UI decoration. Weaknesses relative to the public project are listed in § 14.

## 3. Architecture

```
Patient form / dataset-sample scenario
      │  POST /api/v1/cardiotwin/predict   (JWT, same auth as ClinCase)
      ▼
features.encode_record  ── validate · coerce · impute (training medians) · leakage guard
      ▼
model.CardioModel (numpy)  ── 4 × [standardise → logit → Platt → probability]
      │                       bootstrap ensemble → 80 % interval → confidence
      │                       shrinkage-Mahalanobis + range checks → representativeness
      │                       CAD := max(CAD, LAD, LCX, RCA)  (hierarchical constraint)
      │                       exact additive contributions per target
      ▼
JSON: probabilities · intervals · explanations · warnings · visualization state · provenance
      ▼
React: CadCard / VesselCards / EvidencePanel / TrustPanel / SensitivityPanel
      └─ vesselMapping (the only probability→visual rule) ─► HeartViewer (R3F) LAD · LCX · RCA meshes
```

Reused from ClinCase, not duplicated: JWT auth (`get_current_user`), app shell / sidenav / design tokens,
OncoTwin's artifact convention (JSON + SHA-256 + bootstrap ensemble), `METRICS` telemetry, structured logging with an
input hash (no patient values are logged or stored), the gzip middleware (extended to `/api/v1/cardiotwin/`).
Nothing in the oncology workflow was modified.

| Path | Purpose |
|---|---|
| `backend/app/cardiotwin/schema.py` | feature spec (single source of truth for encoding, validation and the UI form), targets, leakage set |
| `features.py` / `data.py` | encoder, leakage guard, dataset validation + reproducible import |
| `training.py` / `evaluation.py` | nested repeated CV, calibration, thresholds, challengers, audits, artifact + report + scenarios |
| `model.py` | numpy inference, attribution, uncertainty, OOD, counterfactual, sensitivity, model card |
| `backend/app/api/cardiotwin.py` | REST API |
| `frontend/src/cardiotwin/*`, `routes/CardioTwin.tsx`, `routes/CardioEvaluation.tsx` | UI |
| `backend/app/cardiotwin/artifacts/` | `cardiotwin_lr_v1.json` (model), `evaluation.json`, `scenarios.json` |

Extension points: add a clinical feature = one `FeatureSpec` + retrain (form, validation, attribution follow);
add a model family = another artifact behind the `predict / version_info / card` contract; add an anatomical
structure = another entry in `vesselGeometry.ts`. Future modalities (ECG waveform, echo, CT angiography,
longitudinal labs) would enter as new encoded feature groups or a separate model; **no fake versions are shipped**.

## 4. Dataset and preprocessing

Extension of the Z-Alizadeh Sani dataset — UCI id 411, **CC BY 4.0**, 303 rows × 59 columns, 216 CAD (71 %),
LAD 177 / LCX 119 / RCA 114 stenotic. The CSV is committed with attribution and SHA-256 pins
(`backend/data/cardiotwin/README.md`); `python -m app.cardiotwin.data --import` re-derives it from UCI.

* Labels: overall CAD is the **`Cath`** column (there is no `CAD` column). `Cath == any vessel stenotic` in
  302/303 rows.
* Vessel correlations: LAD–LCX 0.363, LAD–RCA 0.282,
  LCX–RCA 0.394; vessel-count distribution {'0': 86, '1': 87, '2': 67, '3': 63}.
* Encoding: Y/N and 0/1 → binary; ordinal (Function Class, RWMA count, VHD severity) → index; Sex, BBB → one-hot;
  constant `Exertional CP` dropped → **55 encoded inputs** from 54 raw features.
* No missing values in the file; at inference missing fields are imputed with the training median and reported
  (feature-completeness metric, warning under 50 %, confidence forced to "low" under 25 %).
* Physiologically-impossible values are rejected with a 422 listing every problem — never silently clipped.

## 5. Leakage prevention

`features.assert_no_leakage` runs inside `train()` **before anything is fit**, for all four targets, and rejects
`Cath`, `CAD`, `LAD`, `LCX`, `RCA` (and encoded forms such as `LAD=Stenotic`, `Cath_CAD`). Every target's model
excludes *all four* label columns, not only its own: a CAD model that saw the vessel labels, or a vessel model that
saw CAD or a sibling vessel, would be reading the answer. The inference encoder also refuses label columns.

Audit results (`evaluation.json → leakage_audit`, status **pass**):

* strongest single feature per target: CAD: Typical Chest Pain (separation 0.598), LAD: Typical Chest Pain (separation 0.465), LCX: Age (separation 0.362), RCA: Typical Chest Pain (separation 0.299) — nothing near-deterministic;
* **label-permutation canary:** CV AUC on shuffled labels = CAD 0.478, LAD 0.491, LCX 0.541, RCA 0.51 (≈ 0.5 expected);
* **bypass demonstration (diagnostic only, never trained/shipped):** letting LAD/LCX/RCA into the CAD model would
  give AUC **0.994** — vs 0.913 honest. That gap is the leak.
* Tests: each label × each target is rejected; a poisoned encoder aborts `train()` with `LeakageError`.

## 6. Models and evaluation

**Shipped:** one L2-regularised logistic regression per target (C tuned by inner 5-fold CV on log-loss),
pre-specified for small-n stability and *exact* attribution. **Challengers** (reported, not used to pick the shipped
model after the fact): L1-LR, random forest (300 trees), gradient boosting (120 depth-2 trees), and a
multi-output random forest as a multi-task probe.

**Protocol.** 3 × repeated stratified 5-fold CV (15 folds), stratified on the number of stenotic vessels and with
*identical folds for all four targets* (so joint analyses are valid). Imputation and scaling are inside each fold's
pipeline; calibration and decision thresholds are fit on the training fold's inner out-of-fold predictions only.
Headline CIs: 1000× patient-level bootstrap of the per-patient out-of-fold predictions (averaged over repeats).
Threshold metrics: mean over folds using each fold's own inner-fold threshold (Youden J).

| Target | Prevalence | ROC-AUC (95% CI) | PR-AUC | Brier | ECE | Accuracy | Precision | Recall | Specificity | F1 |
|---|---|---|---|---|---|---|---|---|---|---|
| CAD | 0.71 | **0.913** (0.876–0.944) | 0.961 | 0.103 | 0.054 | 0.84 | 0.93 | 0.85 | 0.83 | 0.88 |
| LAD | 0.58 | **0.823** (0.776–0.868) | 0.857 | 0.164 | 0.083 | 0.76 | 0.77 | 0.84 | 0.66 | 0.80 |
| LCX | 0.39 | **0.679** (0.615–0.734) | 0.545 | 0.217 | 0.083 | 0.60 | 0.51 | 0.65 | 0.58 | 0.55 |
| RCA | 0.38 | **0.738** (0.682–0.788) | 0.598 | 0.199 | 0.054 | 0.66 | 0.55 | 0.72 | 0.63 | 0.60 |

*n = 303. Precision/recall/F1 are for the positive (stenotic) class. Confusion matrices and ROC / reliability curves
are on `/cardiotwin/evaluation`.* **LCX (AUC ≈ 0.68) and RCA are only modestly
predictable from these features; the CAD estimate is much more reliable than any vessel estimate.**

### Model comparison (per-fold ROC-AUC; Δ = challenger − shipped; Nadeau–Bengio corrected paired t-test)

| Target | L2-LR (shipped) | L1-LR | Random forest | Gradient boosting |
|---|---|---|---|---|
| CAD | 0.918 | 0.935 (Δ+0.018, p=0.07) | 0.924 (Δ+0.007, p=0.59) | 0.924 (Δ+0.007, p=0.64) |
| LAD | 0.832 | 0.834 (Δ+0.002, p=0.87) | 0.857 (Δ+0.025, p=0.28) | 0.838 (Δ+0.006, p=0.78) |
| LCX | 0.680 | 0.705 (Δ+0.025, p=0.33) | 0.746 (Δ+0.066, p=0.06) | 0.734 (Δ+0.054, p=0.15) |
| RCA | 0.740 | 0.756 (Δ+0.016, p=0.26) | 0.710 (Δ-0.030, p=0.19) | 0.705 (Δ-0.035, p=0.16) |

No challenger is significantly better (all p > 0.05); the largest gap is random forest on LCX. Given fold noise
(σ ≈ 0.04–0.07) and the value of exact attribution, the shipped family stays logistic regression.

### Multi-task / hierarchical investigation

* Multi-output RF (trees shared across the 4 targets) vs single-output RF: no significant gain.

| Target | Single-output RF AUC | Multi-output RF AUC | p |
|---|---|---|---|
| CAD | 0.924 | 0.924 | 0.92 |
| LAD | 0.857 | 0.862 | 0.56 |
| LCX | 0.746 | 0.741 | 0.69 |
| RCA | 0.710 | 0.724 | 0.45 |

* **Hierarchical constraint.** Because CAD ⊇ any vessel (302/303 rows), P(CAD) ≥ max(P(LAD), P(LCX), P(RCA)) must
  hold. Independently trained models violated it for **17.5 %** of patients.
  Shipping `max`-projection changes CAD AUC by -0.0006 and CAD Brier
  0.103 → 0.103 (ECE 0.054 → 0.045), i.e. the constraint
  is free. A noisy-OR of vessel probabilities is *worse* (Brier 0.119, ECE 0.105) because vessel labels are correlated.
  When the projection fires the UI says so ("raised from x % …").

## 7. Calibration

Raw vs Platt scaling vs isotonic regression, each fit on inner out-of-fold predictions and scored on the outer fold:

| Target | Brier raw | Brier Platt | Brier isotonic | ECE raw | ECE Platt | ECE isotonic | Shipped |
|---|---|---|---|---|---|---|---|
| CAD | 0.110 | 0.107 | 0.112 | 0.131 | 0.116 | 0.098 | platt |
| LAD | 0.171 | 0.167 | 0.167 | 0.156 | 0.140 | 0.126 | platt |
| LCX | 0.224 | 0.220 | 0.223 | 0.133 | 0.138 | 0.131 | platt |
| RCA | 0.203 | 0.201 | 0.202 | 0.124 | 0.124 | 0.105 | platt |

Rule: ship Platt only if the mean per-fold Brier gain exceeds its standard error (true for all four targets:
CAD +0.0036 ± 0.0024, LAD +0.0041 ± 0.0016, LCX +0.0042 ± 0.0021, RCA +0.0021 ± 0.0020).
Isotonic is reported but not shippable (high-variance step function at n ≈ 300; it would also break exact additive
attribution). The gains are small and per-fold ECE is noisy (≈ 60 test rows); **calibration is measured, not
guaranteed.** The UI shows both the model output and the calibrated probability (`Calibrated · model output 87 %`).

## 8. Uncertainty and representativeness

* **Uncertainty:** 100-member bootstrap ensemble per target → 80 % interval → confidence (high ≤ 0.15 wide,
  moderate ≤ 0.30, else low; downgraded by borderline/outside representativeness or low completeness). Width vs
  absolute error, Spearman ρ: CAD 0.864, LAD 0.624, LCX 0.379, RCA 0.443. *Caveat:* width is largest near p = 0.5, where
  error is too, so part of this is mechanical; the interval is **not** a calibrated confidence statement (conformal
  prediction — see § 2 — would give finite-sample coverage and is future work).
* **Representativeness:** Ledoit–Wolf-shrinkage Mahalanobis distance on standardised features, thresholds at the
  95th/99th percentile of *cross-validated* held-out distances (d² > 140.09 borderline, > 275.9 outside), plus per-feature
  range checks (> 10 % beyond the training range). Output: "Prediction generated, but this profile lies outside the
  well-represented region of the training cohort." **Exploratory:** in this cohort, far-from-centre patients were not
  demonstrably worse predicted (see `evaluation.json`), so this flags *unfamiliarity*, it does not certify or
  quantify error.

## 9. Explanation

The model is linear in standardised features, so attribution is **exact**:
`calibrated_logit = baseline + Σ contribution_j` (equal to interventional SHAP for a linear model with independent
features; multi-column features such as BBB are summed back to their clinical feature). Tests assert the identity.
Each vessel gets its **own** explanation (top drivers per target — LAD: +Typical Chest Pain, +Region RWMA, +Age, -EF-TTE, -Nonanginal, -Atypical; LCX: +Age, +Typical Chest Pain, +Na, +CR, +DM, -PLT; RCA: +DM, +Age, +ESR, +Typical Chest Pain, +Sex, +Poor R Progression;
CAD: +Typical Chest Pain, +Age, +Region RWMA, +DM, +Tinversion, +FH), with the patient value, cohort percentile, reference-range status, direction and share.
"Why LAD is highlighted" describes *model evidence*, not a physical finding. Correlated inputs share credit; a
contribution is not a causal effect.

## 10. Model-sensitivity simulation ("counterfactual")

`POST /counterfactual` re-runs the model with edited inputs and returns before / after / Δ for all four targets
plus `within_model_uncertainty` (|Δ| < ensemble SD). `POST /sensitivity` sweeps one feature across the cohort's 5th–95th
percentile. The UI toggles the 3D view between baseline and perturbed. Always labelled *"model sensitivity
simulation — not a treatment recommendation and not a causal claim"*. Scenario E is found by exhaustive search over
mid-range patients and out-of-range labs moved to their reference bound.

## 11. 3D visualization

Procedural schematic heart (`vesselGeometry.ts`): ventricular body, atria, aorta, pulmonary trunk and three
separately selectable coronary tubes following the textbook grooves. **Why not a downloaded mesh:** no
redistributable, vessel-segmented heart model was available offline, and an unsegmented `.glb` would force us to
fake which triangles are "LAD". Here model id ↔ mesh id is 1:1 by construction, the scene is ~10 k triangles with
zero downloads, and swapping in a licensed BodyParts3D/`.glb` later only touches `vesselGeometry.ts`.

Mapping layer (`vesselMapping.ts`, unit-tested): probability → colour ramp (neutral → amber → red); confidence →
outline strength; ensemble interval width → halo radius. **Vessel thickness is never modulated** (a narrowed tube
would imply anatomical stenosis). Colour is never the only channel — numeric labels, band text and keyboard-operable
vessel buttons accompany the scene. Interaction: orbit / zoom, click a vessel or its tag to select, click empty space
to deselect, "Reset view".

Performance for GPU-less browsers: `frameloop="demand"` (frames only on interaction / state change / colour tween),
DPR ≤ 1.5, `powerPreference: "low-power"`, no textures or shadows, lazy-loaded route chunk, WebGL-unavailable
fallback. In headless Chromium with software rendering (SwiftShader) the first probabilities were visible ≈ 2.2 s
after navigation and the scene rotated and zoomed interactively.

## 12. Dashboard, trust panel and safety

Route `/cardiotwin`: scenario chips (A low CAD, B high CAD, C mixed-vessel, D unrepresentative synthetic, E sensitivity)
or manual entry (auto-predict on edit, debounced, stale responses dropped); CAD card; three vessel cards; evidence
panel; sensitivity panel; **Model trust & provenance** (model + version, SHA-256 integrity check, dataset hash,
leakage-audit status, calibration per target, feature completeness, representativeness, confidence, held-out AUC with
CIs, timestamp, input hash). Dataset-sample scenarios can reveal the record's true angiography labels
("shown for honesty") — the model is sometimes wrong. The disclaimer appears in the page header **and** inside the
3D viewer. `/cardiotwin/evaluation` renders the full report (metrics + CIs, ROC and reliability curves, confusion
matrices, calibration and model comparison, consistency, leakage audit, feature importance, limitations).

## 13. Reproducibility and testing

```bash
cd backend && pip install -e ".[dev]"                 # includes the cardiotwin extra (scikit-learn, pandas, scipy)
python -m app.cardiotwin.data                          # validate dataset + hash
python -m app.cardiotwin.training                      # ≈ 2 min; writes artifacts/{cardiotwin_lr_v1,evaluation,scenarios}.json
pytest tests/cardiotwin                                # 85 tests
cd ../frontend && npm ci && npm test -- --run && npm run build
```

Training is deterministic: three independent full runs produced the identical artifact SHA-256
(`6a509497b7a38b11…`); `training.trained_at` is excluded from the hash. Serving needs only numpy (a test blocks
sklearn/pandas/scipy and still predicts). Missing / corrupt / tampered artifacts fail closed (HTTP 503 with an
actionable message; a one-coefficient edit fails the integrity check).

Tests: data schema / values / targets; leakage (each label × each target, encoded forms, poisoned encoder aborts
training); encoder parity between training and inference; determinism; probability ranges; exact attribution
identity; hierarchical constraint on the whole cohort; counterfactual == direct evaluation and direction;
representativeness; tampering; API auth on every route, schema, 422s, 503 degradation, end-to-end scenario → vessel;
frontend mapping rules, geometry, probability rendering, 3D ↔ card ↔ evidence selection sync, OOD warning display,
sensitivity flow.

## 14. Limitations and adversarial review

**Known limitations.** • Single-centre research dataset, n = 303 (Iran, Shaheed Rajaei Cardiovascular Center); no external validation. • Labels are angiographic stenosis >= 50% per vessel (overall CAD is the `Cath` column); the model estimates these labels, not future events or mortality. • Tabular features only: no images, lesion coordinates or plaque geometry. The 3D view shows a probability per vessel, never a lesion location. • LCX and RCA discrimination is modest (see per-target CIs); vessel-level estimates are far less reliable than the overall CAD estimate. • Calibration is estimated on the same small sample; intervals reflect sampling uncertainty of the model fit (bootstrap), not distribution shift to other hospitals. • Representativeness scoring is exploratory and cannot certify that a new patient resembles the cohort.

| Attack | Response |
|---|---|
| *Clinical researcher:* "Is the visualization anatomically truthful?" | It is not meant to be: a schematic with textbook groove paths, labelled "not a lesion location", constant tube width, probability-only colour. There is no evidence for intra-vessel localisation and none is claimed. |
| *ML researcher:* "Is there leakage?" | Guard + audit + canary + bypass demo (§ 5). Residual risk: single-centre label definitions. |
| *Statistician:* "Small-data accuracy illusion?" | Nested repeated CV, patient-bootstrap CIs, paired corrected tests, chance-level canary; LCX/RCA reported as weak. No external validation — cannot be fixed with this data. |
| *Systems engineer:* "Artifact unavailable?" | Fail-closed 503, integrity check, numpy-only serving, deterministic rebuild. |
| *Judge:* "Couldn't another team build this in two hours?" | The baseline, yes (a public repo exists). The constraint analysis, exact attribution tied to vessel selection, sensitivity simulation, representativeness and reproducible audit trail are the work. |
| *Competitor:* "Novelty = SHAP + Three.js?" | Partly, honestly: those are the baseline. We claim integration rigor and claims-discipline, not research novelty (§ 2). |
| *Medical reviewer:* "Could someone mistake probability for diagnosis?" | Disclaimer in header and viewer; "estimated", "model evidence", "not a lesion location" wording; reference labels show errors; low-confidence / OOD states are loud. Residual risk remains for any risk UI. |

**Weaknesses vs. the public project:** its anatomy comes from a real BodyParts3D mesh (ours is schematic); it may
use nonlinear boosted trees (ours stays linear by design; challengers were not significantly better here). Name
collision with that repository.

**Cannot be responsibly fixed here:** external validation, population calibration, bias/subgroup analysis (sex and
age subgroups are far too small), regulatory review, conformal coverage guarantees, a licensed vessel-segmented mesh.

## 16. Demo flow (≈ 3 min)

1. `/cardiotwin` loads scenario C → CAD 99 %, **LAD 88 %, LCX 41 %, RCA 21 %** — three different colours on three arteries.
2. Click LAD in the 3D scene → "Why LAD is highlighted": EF, RWMA, chest pain, T-inversion; exact additive breakdown.
3. Click RCA → a different explanation. Note halos/outlines and the legend ("colour is not a stenosis measurement").
4. Scenario E → sensitivity simulation: one lab value moved to its reference bound; LAD 84 % → 67 %, before/after/Δ,
   flip the 3D view between baseline and perturbed.
5. Scenario D → *"Prediction generated, but this profile lies outside the well-represented region…"*, low confidence.
6. Trust panel (integrity ✔, leakage audit ✔) → `/cardiotwin/evaluation`: CIs, calibration, the weak LCX result, the
   17.5 % consistency violations, the 0.994-vs-0.913 leakage demonstration.
